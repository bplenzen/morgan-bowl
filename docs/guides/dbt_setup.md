# dbt Setup Plan

## Goal

Model Sleeper ingestion outputs in DuckDB using dbt Core to deliver staged and mart tables for analytics.

## Prerequisites

- DuckDB warehouse populated via `python -m ingestion.cli` (tables under `staging` schema: `league`, `users`, `rosters`, `matchups_week_*`, `transactions_week_*`).
- Python environment managed by Poetry with dbt-duckdb adapter (to be added).
- `profiles.yml` configured to point to the DuckDB file at `data/processed/warehouse.duckdb`.

## Step-by-step

1. **Install dbt tooling**
   - Add dependencies: `poetry add dbt-core dbt-duckdb`.
   - Update `.pre-commit-config.yaml` with optional `sqlfluff` hook for dbt linting.
2. **Initialize project**
   - `poetry run dbt init morgan_bowl --profiles-dir ./.dbt` (or manual scaffold in `dbt/`).
   - House dbt project under `dbt/` with subdirectories `models/staging`, `models/marts`, `seeds`, `snapshots`.
3. **Configure profile**
   - Create `dbt/profiles.yml` template referencing `${DUCKDB_PATH}` (env) and using DuckDB adapter with `schema: analytics` for models.
   - Document local setup in README (how to symlink/copy to `~/.dbt/profiles.yml`).
4. **Source definitions**
   - Define sources for `staging.league`, `staging.users`, `staging.rosters`, weekly matchups/transactions (use regex or exposures for dynamic tables).
   - Implement macros to union weekly tables into canonical staging views.
5. **Staging models**
   - Create `stg_league`, `stg_users`, `stg_rosters`, `stg_matchups`, `stg_transactions` applying renames, type casting, and array flattening.
   - Apply tests: `not_null`, `unique`, `relationships`; add `dbt_exposure` for Lightdash/Metabase.
6. **Mart models**
   - Build `dim_players`, `dim_teams`, `fct_matchups`, `fct_transactions` using staging tables and metadata.
   - Calculate derived metrics (points for/against, win/loss flags, waiver cost) and attach docs.
7. **Snapshots & seeds**
   - Optional: snapshot player data to track changes, seed static lookups (position groups, scoring multipliers).
8. **Docs & artifacts**
   - Enable `dbt docs generate`; publish docs via GitLab Pages artifact or README link.
   - Commit `manifest.json` outputs as CI artifact.
9. **Testing & CI**
   - Update GitLab CI to run `poetry run dbt deps && poetry run dbt build` on merge requests using DuckDB file generated from sample data.
